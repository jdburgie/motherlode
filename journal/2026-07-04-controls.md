# PyGamer Controls Repair Journal

## 2026-07-04

After the first successful firmware build and flash, Motherlode displayed its title screen but did not respond to buttons or joystick input.

### Input timing finding

The pinned `PyGamer.Controls` implementation toggles the 74HC165 button shift-register latch and clock and reads the data pin immediately. At the PyGamer CPU clock of 120 MHz, those transitions can occur faster than the external shift register's setup, hold, and pulse-width requirements.

Working PyGamer implementations insert short delays between latch, clock, and data operations.

A repository-local `Controls` package was added so the application can use a corrected implementation without modifying the pinned BSP submodule. The local driver:

- Initializes button clock and latch high.
- Adds settling delays around latch and clock transitions.
- Reads A, B, Start, and Select from the shift register.
- Reads the analog joystick using ADC1.
- Uses a slightly lower joystick threshold for menu navigation.
- Is used by the title screen, main game, cargo menu, and equipment menu.

### Namespace regression found during the repair

The first local-driver build failed with:

```text
controls.adb:69:40: "Clk_48Mhz" is undefined
```

Cause:

The original driver was the child package `PyGamer.Controls`. As a child unit, it could see the private `Clk_48Mhz` shortcut declared in the parent `PyGamer` package. The new repository-local `Controls` package is a top-level package and does not inherit that private visibility.

An intermediate attempt incorrectly qualified the constant as `SAM.Clock_Generator.Clk_48Mhz`. `SAM.Clock_Generator` defines the generator ID type and configuration operations, but does not define that board clock assignment.

Final correction:

```ada
with SAM.Clock_Setup_120Mhz;

SAM.Clock_Generator.Configure_Periph_Channel
  (SAM.Clock_Generator.IDs.ADC1,
   SAM.Clock_Setup_120Mhz.Clk_48Mhz);
```

Lesson:

Moving code out of an Ada child package can remove visibility inherited from the parent package, including private declarations. Any formerly unqualified board constants must be traced to their public defining package rather than guessed from their type.

### SD-card status

The PyGamer hardware has an SD-card SPI connection, but this Motherlode branch does not yet contain an SD block driver, FAT filesystem integration, file loading, or save-game support. The SD slot is therefore not used by the game yet.
